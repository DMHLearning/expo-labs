# Lab 2 - Markers App 👋

Это React Native приложение на базе Expo для создания и управления маркерами на карте. Маркеры хранятся в локальной SQLite базе данных, с возможностью добавления/удаления изображений. Приложение использует контекст для управления данными, асинхронные операции и обработку ошибок.

## Установка

1. **Требования**:
   - Node.js
   - Expo CLI
   - Android Studio / iOS Simulator для тестирования

2. **Клонирование репозитория**:
   ```
   git clone https://github.com/DMHLearning/expo-labs
   cd expo-labs
   ```

3. **Установка зависимостей**:
   ```
   npm install
   ```

4. **Запуск приложения**:
   - Для разработки: `expo start`
   - Для Android: `expo start --android`
   - Для iOS: `expo start --ios`
   - Убедитесь, что у вас настроен Expo Go на устройстве или эмулятор.

## Схема базы данных

База данных использует SQLite и хранится в файле `markers.db`. Схема состоит из двух таблиц:

### Таблица `markers`
- `id`: INTEGER PRIMARY KEY AUTOINCREMENT — уникальный идентификатор маркера.
- `latitude`: REAL NOT NULL — широта.
- `longitude`: REAL NOT NULL — долгота.
- `created_at`: DATETIME DEFAULT CURRENT_TIMESTAMP — дата создания.

### Таблица `marker_images`
- `id`: INTEGER PRIMARY KEY AUTOINCREMENT — уникальный идентификатор изображения.
- `marker_id`: INTEGER NOT NULL — ссылка на маркер (FOREIGN KEY REFERENCES markers(id) ON DELETE CASCADE).
- `uri`: TEXT NOT NULL — URI изображения.
- `created_at`: DATETIME DEFAULT CURRENT_TIMESTAMP — дата добавления.

Инициализация таблиц происходит автоматически при запуске в `DatabaseContext.tsx`. Каскадное удаление обеспечивает автоматическое удаление изображений при удалении маркера.

## Подход к обработке ошибок

Обработка ошибок реализована на нескольких уровнях для надежности и удобства пользователя.

- **Транзакции**. Все CRUD-операции (addMarker, addImageToMarker и т.д.) обернуты в `executeTransaction`, которая использует try-catch для ошибок SQL. Транзакции обеспечивают атомарность (все или ничего).
- **Асинхронные загрузки**. В UI-компонентах (index.tsx, [id].tsx) используются try-catch вокруг await-вызовов. При ошибках показываются Alert.alert с сообщениями.
- **Статусы**. Контекст предоставляет `isLoading` и `error` для отображения лоадеров или ошибок в UI.
- **Логирование**. В режиме разработки логируются успешные транзакции и ошибки в консоль.
- **Очистка**. При размонтировании закрывается соединение с БД для предотвращения утечек.

## Дополнительные реализованные возможности

- **Асинхронная загрузка**. Маркеры и изображения загружаются из БД асинхронно, с обновлением state после операций.
- **Разрешения и ImagePicker**. Запрос разрешений на галерею перед добавлением изображений, с обработкой отказов.
- **Таймаут для карты**. Если карта не загружается за 10 сек, показывается ошибка (проверка ключей/интернета).
- **Мемоизация**. UseCallback для методов контекста и обработчиков, чтобы избежать ненужных ререндеров.
